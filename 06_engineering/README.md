# 第 7 篇 工程实践与部署（Engineering and Deployment）

**章号 20~21** ｜ 前置：任意一个能跑通的模型

章节清单与状态看 [SYLLABUS 第 7 篇](../SYLLABUS.md)。原框架的「实战项目」升级成
「项目流程 + 部署监控」两章，具体项目降为**贯穿各篇的实践轨道**，不占章号。

## 实践轨道（`projects/`）

| 项目 | 用得到的章 | 目录 |
|---|---|---|
| 表格数据端到端 | ch03~ch10 | `projects/tabular/` |
| 图像分类（迁移学习） | ch14~ch17 | `projects/image_classification/` |
| **以图搜图 / 图像检索（终点目标）** | ch11~12 / ch14~19 / ch21 | `projects/image_retrieval/` |
| 模型服务化 Demo | ch21 | `projects/serving_demo/` |

终点目标是**以图搜图（Image Retrieval）**：用预训练模型把图片变成向量，
再围绕「找相似」把前面各篇串成一条能跑的链路。**不需要标注数据、不需要 GPU**。

```
图像集（几百张即可） → 预训练模型抽 embedding → 降维 / 聚类（ch11、ch12）
   → 建向量索引 → 查询服务（ch21） → 召回率 / 延迟评估
   → 新图加入后的漂移监控（ch21）
```

它和「图像分类（迁移学习）」是**递进关系**：分类项目练「训练 / 微调」，
检索项目练「把学到的表示用起来 + 工程化」，两者可共用同一份图像集和同一个骨干模型。
选它当终点，是因为它能同时落到 ch11/12（无监督）、ch14~17（表示学习）、
ch18/19（向量检索 / embedding）和 ch20/21（项目流程 / 部署监控）——
第 7 篇讲「怎么把模型变成能用的东西」，检索比检测更贴合这条主线。

框架阶段只建目录，做的时候再决定图像来源、骨干模型、索引方案和查询页形式。

## 每个项目的固定交付物

1. `README.md`：目标、数据来源、复现步骤、结果指标
2. 能从头跑通的脚本（`src/` 或单个 `.py`）
3. `notes.md`：踩过的坑 + 为什么这么选（比代码更值钱）

> `.gitignore` 已排除数据集与权重（`.pt` / `.onnx` / `.csv`），
> **不要往仓库里放大文件**。项目不强制配 `exercises/`，但脚本要能 smoke test。
